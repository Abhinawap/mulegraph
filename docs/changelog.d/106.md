### 26 Nov 2026 — Audit gate: guard-test idioms, one git command per call, pre-existing findings (#106)
- **Changed** `CLAUDE.md` → Testing: a guard test compares the whole output with `==`, never `in` or a regex; copies mock arguments at call time; and computes its expected values before the run. Three of the nine audit rounds in #66 were this one bug family.
- **Changed** `CLAUDE.md` → Repository Etiquette and Commands: in a worktree session, run each git command in its own call. The snapshot step is now `git add -A`, then `git stash create`, and the narrowed integrity run takes its paths from a separate `git diff`, since the harness refuses compound git commands. `--rows-for-base` is #107.
- **Changed** `.claude/agents/integrity-auditor.md` and the `CLAUDE.md` gate sentence: a finding whose row plants verbatim on the base, with the base's own version of its guard test still passing there, is reported as **Pre-existing** and does not block. The auditor returns PASS and lists them; that PASS counts once each has an issue number in the PR body. Four of the nine rounds in #66 blocked on gaps that were already on main.
