### 14 Nov 2026 — Every output sink in pipeline.py is planted or excused (#70)
- **Added** `test_every_output_sink_is_planted_or_excused` (`tests/test_integrity_mutants.py`). It parses `pipeline.py` and lists every output: a call whose dotted name, with imports and aliases resolved (relative ones included), starts with a `SINK_PREFIXES` entry (`mulegraph.report.`, `mlflow.log_`, `mlflow.set_tag`); a method in `SINK_METHODS` (`to_csv`, `to_parquet`, `write_text`, `save`, `savefig`); or the return value of a `run_*` function, since the CLI exits 3 on `run_score`'s. A new `mulegraph.report` writer needs no edit to the test, however it is imported. Each output must overlap a row's site or appear in the new `UNSUNK` dict, keyed `function: source`, with the reason no threshold-derived value reaches it (provenance tags and params, config files, the predictions file the guards re-derive from, the booster, the results table, which reads metrics planted where they are logged, and returned paths). The keys are compared as lists: a copy of an excused output in another function needs its own entry, and one in the same function fails until it gets a row. `test_a_new_output_is_seen_by_the_sink_scan` adds outputs in each import form plus a copy of an excused call, and requires every one to show. Not seen: output kinds missing from the two constants (`json.dump`, `.to_json`, `fh.write`), and a new metric key inside a `log_metrics` call that is already planted. The threshold-token check (`UNPLANTED`) is unchanged and shares the planted-line helper.
- **Rows** (62 in all): one per threshold-bearing sink that had none at the line that writes it. Each plants a test-searched threshold in what that line writes: the curves CSV (benchmark test), the drift scores, lead and event CSVs (drift end-to-end test), the alerts CSV, health file and returned drift flags (queue test), and the deployed model's cached meta file (`test_a_second_batch_reuses_the_deployed_model`). Five more plant it in values inside outputs already planted, which the per-call scan cannot see: the deployed model's cached `val_f1`, the health file's `flagged` list, alert count and `model_fit` threshold, and the report page's flags. The cached `val_f1` row recomputes an F1, so it joins `HONEST` and its control. The `ts_*` logging row's site now covers its `mlflow.log_metrics` call. The `plot_curves` and `plot_drift` lead-table rows share their setup plants (`BAD_CURVES`, `BAD_LEADS`) with the new CSV rows.
- **Tests** (`tests/test_score.py`): the queue test pins ten licit scored-batch units between the validation and the test-searched threshold, so the alert-rate flag differs at the two and the test asserts it does. It also asserts that the drift flags `run_score` returns equal the health file's, and that the health file's status matches its flags (it asserts that `conf`, which never reads the threshold, flags, so no row can plant a test-searched status). The reuse test checks both days' threshold, and the cached threshold and `val_f1`, against a validation optimum it fits outside `run_score`.
