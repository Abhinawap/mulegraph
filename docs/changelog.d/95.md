### 25 Nov 2026 — The sink scan checks each dict entry (#95)
- **Changed** `_unsunk` (`tests/test_integrity_mutants.py`) treats each entry of a dict literal that reaches an output as an output of its own. A dict counts when it is passed straight into a planted sink call, or bound to a name (plainly or with an annotation) that a sink call in the same function takes at any depth (`run_score`'s `report`, `_deployed_model`'s `meta`). A `**splat` is one entry. Nested values and dict comprehensions are not expanded, and neither is a dict passed into a call `UNSUNK` excuses whole (`log_params`, `set_tags`), whose key already changes when it gains an entry. An entry is planted when a row's site overlaps the character span of its value, not just its line or its key, so a one-line dict like `meta` is checked entry by entry. Otherwise it needs an `UNSUNK` reason keyed `function: name[key] = value` (a splat: `function: name[**value]`), so an excused entry whose value changes needs a new reason, as a whole-call key already does. This closes the "new metric key inside a planted `log_metrics`" ceiling from #70, and its `ponytail:` comment is gone. `test_a_new_dict_entry_is_seen_by_the_sink_scan` adds an entry to a multi-line dict passed by name, a one-line one beside planted entries, a splat and a dict passed straight in, and shows each one. It also shows an annotated binding is scanned, a new value in an excused entry shows, a site over a key alone (`fit_seconds`) plants nothing, and a `log_params` dict is not expanded. Still not seen: a dict built in one function and written in another, a dict literal nested inside a sink's arguments (`json.dumps({...})`), keys set after the literal (`d[k] = v`, `.update`), tuple-target or walrus bindings, and the rest of a value a site partly covers (the `detectors` entry is planted by sites inside its comprehension's element, so its loop source is not checked).
- **Rows** (66 in all): the health file's `status` and alert count, and the benchmark child run's logged `test_*` metrics and `diag_*` entries, each at a test-searched threshold. Ten entries carry no threshold-derived value and are excused: the deployed model's definition and commit, validation PR-AUC, the early-stopping round, the fit's seconds, and the health file's batch, reference window, unit count, commit and note.
- **Tests** (`tests/test_score.py`): `test_status_follows_the_alert_flag_at_the_validation_threshold` runs the score path with only the alert-rate detector. It checks that a test-searched threshold would flip the flag, and that the health file's status matches the flag recomputed at the validation threshold, and that the run leaves its config unchanged. With `conf` in the set the status never moved, so no row could plant it before. `_honest_fit` has a typed return.
- **Changed** the deployed model's cached `val_f1` row ends its site at the `"commit"` key, so it no longer counts as planting the commit it leaves unchanged.
- **Changed** the `UNSUNK` comment: some excuses hold because the value is tested where it is first written. `.claude/agents/integrity-auditor.md` describes the per-entry scan and what it still misses. Design §3.7 lists the status test.
