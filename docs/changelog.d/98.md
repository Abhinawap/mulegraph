### 25 Nov 2026 — The sink scan plants only what a row changes (#98)
- **Changed** `_planted_sites` (`tests/test_integrity_mutants.py`) returns each `pipeline.py` row's changed span (its `site` minus the prefix and suffix it shares with `broken`) instead of the whole site, so an output or dict entry is planted only where the bytes a row's `site` edit changes fall on it (`also` edits never count). The full common prefix and suffix are stripped; when they overlap the span is inverted, an insertion that may sit anywhere between its ends (`**scored` → `**s, **scored`), and it plants only a value that strictly contains it. A row whose `site` edit leaves the parsed code unchanged (a comment, a space) plants nothing. A pure insertion is a zero-width point that plants a value only when it lands strictly inside it, which replaces the `site not in broken` rule. An insertion at a value's boundary (`**scored` → `**scored | {...}`) fails closed: the row has to be respelled. A `ponytail:` comment names the known hole (two separate edits in one site still plant an entry left verbatim between them) and the upgrade path (diff the parsed outputs before and after each plant). `UNPLANTED` and `UNSUNK` are unchanged.
- **Rows**: the benchmark child run's logged `test_*` and `diag_*` rows are respelled to `**{**scored, ...}` and `**{**diagnostics, ...}`; the `ts_*` row now changes `getattr(row, name)` inside the `log_metrics` call, with the test-threshold curve zipped in on the `for` line. Each still fails `LOGGED_F1` from the same assertion.
- **Tests**: `test_a_row_plants_only_the_entries_its_changed_bytes_overlap` injects one synthetic row per case: a site over `"val_f1": ..., "commit": commit` that changes only `val_f1` plants `meta[val_f1]` and not `meta[commit]`; `**{**scored, ...}` plants `[**scored]`; `**scored | {...}`, `**s, **scored` and a `ts_*` site edit that changes nothing or adds only a comment do not. The `fit_seconds` case of `test_a_new_dict_entry_is_seen_by_the_sink_scan` inserts its entry after `fit_seconds` instead of replacing that line, which broke the anchor of the `val_f1` row.
- **Changed** `_planted_lines`, which feeds the threshold-line check, uses the same overlap rule per line: a line is planted when a changed span overlaps its code (indentation and trailing space stripped), so an insertion just before a line's code (the two `diag_*` rows' `DIAG_AT_TEST`) no longer plants it. `test_an_insertion_plants_a_line_only_strictly_inside_its_code` pins both sides.
- **Changed** `tests/test_integrity_selection.py` (after merging #99): the two new unmarked tests join `META`, and the narrowed-run check compares parametrized cases by function name.
- **Changed** `.claude/agents/integrity-auditor.md` describes the changed-bytes rule, the two-edits hole, and a site edit that changes the code but not what it writes with the bug in `also`, which no byte or AST scan sees.
